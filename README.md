# TCP checkers

Настольное приложение на `Windows Forms` для игры в шашки по сети через `TCP`. Проект реализует локальную игровую логику, обмен ходами между двумя участниками и поставляется вместе с тестами, графическими ресурсами, публикационной сборкой и сценарием создания установщика.

## Описание

Приложение предназначено для запуска партии в шашки между двумя игроками по TCP-соединению. Один участник поднимает сервер, второй подключается по IP-адресу и порту. После установки соединения игра синхронизируется через обмен JSON-сообщениями, а правила шашек обрабатываются внутри общего игрового движка.

По коду интерфейса и установщика приложение отображается под названием `Шашки по сети`.

## Возможности

- Создание TCP-сервера из интерфейса приложения.
- Подключение ко второму игроку по IP-адресу и порту.
- Отображение доски `8x8` с графическими изображениями обычных шашек и дамок.
- Автоматический разворот доски для игрока, играющего черными.
- Проверка корректности ходов по правилам игры.
- Поддержка обязательного взятия.
- Поддержка последовательного взятия одной и той же шашкой.
- Превращение шашки в дамку при достижении крайнего ряда.
- Определение победителя по количеству фигур и доступности ходов.
- Обмен служебными сетевыми сообщениями: подключение, ход, завершение партии, новая игра, отключение.
- Журнал сообщений о состоянии соединения и ходе партии.

## Архитектура и технологический подход

Проект разделен на несколько логических слоев:

- `project/MainForm.*` отвечает за пользовательский интерфейс, запуск сервера, подключение клиента, обработку нажатий на доске и отображение статуса партии.
- `project/GameLogic/` содержит игровую модель и правила: инициализацию доски, проверку ходов, обязательные взятия, цепочки взятий, смену хода и определение победителя.
- `project/Network/` реализует TCP-сервер и TCP-клиент, прием и отправку сообщений, а также обработку разрыва соединения.
- `project/Models/` содержит доменные модели игры и контракт сетевых сообщений.
- `project.Tests/` покрывает модульными тестами ключевые сценарии игровой логики.

### Обработка партии

`CheckersGame` управляет состоянием партии и публикует события `BoardChanged` и `GameStateChanged`, на которые подписан интерфейс. После успешного хода состояние обновляется локально, затем ход отправляется второму игроку в виде `NetworkMessage`.

### Правила игры

`MoveValidator` реализует:

- проверку диагональных ходов;
- разную механику для обычной шашки и дамки;
- обязательность взятия;
- поиск доступных ходов для игрока;
- проверку возможности дополнительного взятия той же фигурой.

### Сетевое взаимодействие

Классы `TcpGameServer` и `TcpGameClient` используют текстовый обмен сообщениями в кодировке `UTF-8`. Сообщения передаются построчно и сериализуются в JSON через `NetworkMessage`. В коде используются типы сообщений:

- `connect`
- `move`
- `gameOver`
- `newGame`
- `error`
- `disconnect`

## Требования

Для разработки и запуска из исходников по содержимому репозитория требуются:

- `Windows` как целевая ОС, поскольку приложение использует `Windows Forms` и таргетируется на `net8.0-windows`.
- `.NET SDK 8.0` для сборки, запуска и тестирования.
- Свободный TCP-порт, например `5000`.

Дополнительно:

- `Inno Setup` нужен только для пересборки установщика из `installer/CheckersSetup.iss`.
- Для публикации в текущем профиле используется `RuntimeIdentifier=win-x64` и `SelfContained=true`, поэтому профиль ориентирован на `Windows x64`.

## Установка

### Запуск из исходников

1. Установить `.NET SDK 8.0`.
2. Перейти в корень репозитория.
3. Восстановить зависимости и собрать проект:

```powershell
dotnet build .\project\project.csproj
```

### Использование готовой сборки

В репозитории уже присутствуют:

- каталог `publish/` с опубликованным приложением;
- файл `installer/CheckersSetup.exe` с готовым установщиком.

## Конфигурация

В проекте не обнаружены файлы `.env`, `.env.example`, `appsettings.json`, `appsettings.*.json` или иные отдельные конфигурационные файлы с переменными окружения.

Настройки подключения вводятся вручную в интерфейсе приложения:

- `IP-адрес`
- `Порт`

Значения по умолчанию, заданные в коде:

- IP-адрес: `127.0.0.1`
- Порт: `5000`

Важно учитывать, что некоторые служебные файлы привязаны к локальным абсолютным путям автора:

- `project/Properties/PublishProfiles/FolderProfile.pubxml`
- `installer/CheckersSetup.iss`

При переносе проекта на другую машину эти пути, вероятно, потребуется скорректировать.

## Запуск проекта

### Локальный запуск приложения

```powershell
dotnet run --project .\project\project.csproj
```

### Базовый сценарий использования

1. На первом компьютере нажать `Создать сервер`.
2. На втором компьютере указать IP-адрес первого и тот же порт.
3. Нажать `Подключиться`.
4. После обмена сообщением `connect` начать партию.

## Тестирование

Тестовый проект `project.Tests` покрывает игровую логику и проверяет, в том числе, следующие сценарии:

- стартовую расстановку фигур;
- переходы состояний игры;
- запрет некорректных ходов;
- обязательное взятие;
- цепочку взятий;
- превращение в дамку;
- определение победителя.

При локальной проверке команда

```powershell
dotnet test .\project.Tests\project.Tests.csproj --no-build
```

выполнилась успешно: пройдено `18` тестов.

## Сборка и деплой

В репозитории не обнаружены `Dockerfile`, `docker-compose`, конфигурации CI/CD или сценарии облачного деплоя.

Фактически в проекте реализованы два способа поставки:

- публикация self-contained сборки в каталог `publish/`;
- создание Windows-установщика через `Inno Setup`.

Профиль публикации `FolderProfile.pubxml` задает:

- конфигурацию `Release`;
- целевую платформу `win-x64`;
- self-contained режим;
- вывод в каталог `publish/`.

## Ограничения и наблюдения

- Проект ориентирован на настольный Windows-сценарий и не рассчитан на кроссплатформенный запуск.
- В репозитории отсутствуют Docker-артефакты, переменные окружения и CI/CD-конфигурации.
- В `installer/CheckersSetup.iss` и профиле публикации используются абсолютные пути, что снижает переносимость сборочного процесса без дополнительной правки.
